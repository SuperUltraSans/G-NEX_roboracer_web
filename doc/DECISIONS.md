# 결정 기록

지시서(`doc/Instruction.md`, `doc/Design.md`)와 다르게 정했거나, 지시서가 비워 둔 부분을 채운 결정을 적는다.
형식: 날짜 · 결정 · 이유 · 대안.

## 2026-10-12

### 문서 위치는 `doc/`
- 결정: 지시서가 말하는 `docs/DECISIONS.md`, `docs/DESIGN_DIRECTIONS.md`, `docs/DESIGN_REVIEW.md`는 모두 `doc/`에 둔다. 지시서 본문도 루트의 `INSTRUCTIONS.md`, `DESIGN.md`가 아니라 `doc/Instruction.md`, `doc/Design.md`에 있다.
- 이유: 사용자가 지시서를 `doc/`에 넣었다. `doc/`와 `docs/`를 함께 두면 헷갈린다.
- 대안: `docs/`로 옮기기.

### TypeScript 5.9 고정
- 결정: create-vite 기본값인 TypeScript 6.0 대신 `~5.9`를 쓴다.
- 이유: `openapi-typescript` 7.x의 peer 범위가 `typescript@^5.x`라서 6.0과 함께 설치되지 않는다.
- 대안: `--legacy-peer-deps`로 강제 설치(이후 `npm ci`마다 같은 플래그가 필요해진다).

### 린터는 eslint
- 결정: create-vite 9가 기본으로 넣는 oxlint를 지우고 지시서대로 eslint(flat config, typescript-eslint, react-hooks, react-refresh) + prettier를 쓴다.
- 이유: 지시서 2장.

### 테스트 경고 필터
- 결정: `starlette.testclient`가 `httpx` 대신 `httpx2`를 권하는 DeprecationWarning을 pytest 설정에서 무시한다.
- 이유: 지시서가 테스트 의존성으로 `httpx`를 지정했다. 지금 버전에서는 동작에 문제가 없다.
- 대안: `httpx2`로 교체.

### 서브패스 배포 지원 (`/roboracer`)
- 결정: 개발용 미리보기 서버에서는 HTTPS 리버스 프록시 뒤 `/roboracer/` 경로로 서빙한다. 프록시가 `/roboracer` 프리픽스를 떼고 넘기므로 백엔드는 프리픽스를 모른다.
  - 프론트: 빌드 시 `VITE_BASE_PATH=/roboracer/`. 라우터 `basename`, API·WebSocket 주소는 모두 `import.meta.env.BASE_URL`에서 만든다. 개발 서버는 기본값 `/`.
  - 백엔드: 설정 `COOKIE_PATH`를 추가했다(기본 `/`). 같은 호스트의 다른 앱으로 세션 쿠키가 가지 않도록 서브패스 배포에서는 그 경로(`/roboracer`)로 둔다.
- 이유: 사용자 지시(2026-10-12). 학교 서버의 공개 경로가 정해지지 않았으므로 루트(`/`)와 서브패스 양쪽에서 같은 코드가 동작해야 한다.
- 대안: 앱이 프리픽스를 직접 서빙(FastAPI `root_path` + 라우트 프리픽스). 학교 서버 경로가 바뀔 때마다 백엔드 설정도 바꿔야 해서 택하지 않았다.

### Docker Compose 실행 (P2를 앞당김)
- 결정: 루트에 멀티 스테이지 `Dockerfile`(Node 24로 프론트 빌드 → Python 3.12 + uv 런타임)과 `docker-compose.yml`(포트 8000, `backend/data` 볼륨)을 둔다. 컨테이너는 시작할 때 `alembic upgrade head` 후 uvicorn을 워커 1개로 띄운다. 서버마다 다른 설정은 git에 올리지 않는 `docker-compose.override.yml`에 두고(compose가 자동으로 함께 읽는다), 서브패스·프록시 네트워크 예시는 `docker-compose.override.example.yml`로 커밋한다.
- 이유: 사용자 지시(2026-10-12, "도커 컴포즈로 실행할 수 있게").

### 디자인 시안: 세 개 모두 구현하고 전환 (Design.md Step A)
- 결정: 사용자가 시안 하나를 고르는 대신 "3개 다 구현하고 요청할 때마다 전환"을 골랐다. 구조(페이지, 컴포넌트)는 하나이고, 시안별 차이는 `<html data-design="pitwall|poster|sensor">` 아래의 토큰(서체, 표시 굵기·폭, 반경)과 소개 페이지의 히어로·소개 섹션 변형 컴포넌트로 나눈다. 다른 페이지는 같은 구조에 토큰만 다르고, 일정 페이지의 시간축처럼 필요한 곳만 `[data-design]` 선택자로 조정한다.
- 전환 방법:
  - 관리자 설정 `design`(site_settings 키, 백엔드 `AdminSettings`·`PublicSettings`에 추가). 저장하면 `content.updated(settings)`로 열려 있는 화면에도 바로 반영된다. 비우면 기본값 피트월.
  - 미리보기: URL `?design=<id>`(이 탭의 sessionStorage에만 저장, `?design=default`로 해제).
  - 우선순위: 미리보기 → 관리자 설정 → 마지막으로 본 시안(localStorage) → 피트월.
- 서체: 현재 시안의 서체만 동적 import로 불러온다(`@fontsource` 자체 호스팅, 한글은 unicode-range 분할). 외부 CDN에 의존하지 않는다.
- 이유: 사용자 선택(2026-10-12). Design.md 5.7의 "라이트/다크 전환을 만들지 않는다"는 방문자용 토글을 금지한 것이고, 이 전환은 운영자 설정이라 충돌하지 않는다. 방문자에게 보이는 전환 UI는 두지 않는다.
- 추가 의존성: `@fontsource/ibm-plex-sans-kr`, `@fontsource/ibm-plex-mono`, `@fontsource/black-han-sans`, `@fontsource-variable/anybody`, `@fontsource/gothic-a1`, `@fontsource-variable/geologica`(서체 자체 호스팅), `@playwright/test`(Design.md 8장 스크린샷 점검, devDependency), `sharp`(Design.md 6.8, devDependency).

### 히어로 이미지
- 원본: 사용자가 대화에 첨부한 이미지를 `frontend/assets-src/hero/hero-source.png`(1672×941, PNG)로 저장했다. 세로형 원본은 없다.

- 세로형 원본이 없으므로 좁은 화면에서는 `object-position: 72% 50%`로 차가 보이게 크롭한다.
- 밴딩 점검(`design-review/hero-banding/`): 하단 왼쪽의 어두운 그라데이션 구간(520×360)을 잘라 대비를 4배로 올리고 2배 확대해 원본과 비교했다.
  - 1차(avif 50, webp 75, jpg 78): webp에 16px 블록 띠가 뚜렷했고 avif는 얼룩, jpg는 약한 블록이 보였다.
  - 2차(avif 62, webp 88, jpg 86): jpg는 원본과 구분이 어렵고 avif는 약한 얼룩만 남았다. webp는 가장 아래 구간에 아주 약한 블록이 남지만, 대비를 4배로 올렸을 때만 보이고 그 구간은 CSS 하단 페이드(→ `--ink-900`)가 덮는다. 2차 값으로 확정했다.
  - 용량(1672px): avif 87KB, webp 161KB, jpg 181KB. 예산(avif 250KB, jpg 400KB) 안이다.

### 백엔드 구현 중 채운 결정
지시서가 정하지 않은 부분을 다음과 같이 정했다.
- 매치의 `version`은 슬롯이 바뀔 때마다(슬롯 편집, 진출 전파, 되돌리기, 시드 채우기) 오른다. 오래된 대진 상태로 결과를 입력하지 못하게 하기 위해서다. `PATCH /bracket/slots/{id}`는 새 version이 담긴 상위 매치를 돌려준다.
- `version`은 결과 입력에서만 필수이고, `/reopen`과 `/void`에서는 보낼 때만 검사한다.
- 추가 오류 코드: `INVALID_CREDENTIALS`(401), `MATCH_NOT_FINISHED`(409), `MATCH_FINISHED`(409), `BRACKET_EXISTS`(409), `DUPLICATE`(409), `LAST_ADMIN`(409), `METHOD_NOT_ALLOWED`(405), `INTERNAL_ERROR`(500). 요청 본문의 없는 id는 422, 경로의 없는 id는 404.
- CLI로 만든 데이터는 기록자(`recorded_by`, `audit_logs.user_id`)가 비어 있을 수 있다. 기본 계정이 없기 때문이다.
- 순서 변경은 모든 id를 정확히 한 번씩 보내야 하고 version을 올리지 않는다. `sort_order` 없이 만들면 맨 뒤에 붙는다. `is_published`, `is_active` 기본값은 true다.
- `PUT /settings`는 모든 값을 교체한다(빠진 값은 비움). 시각은 UTC로 저장한다.
- 비활성 팀에는 새 랩, 새 슬롯 배정, 트랙 위 지정을 할 수 없다. 이미 들어간 대진 슬롯에는 남겨서 지난 결과를 읽을 수 있게 한다.
- 슬롯 추가 검증: 한 매치 안에서 팀, 시드 순위, 출처가 겹칠 수 없다. `source_rank`는 출처 매치의 슬롯 수를 넘을 수 없다. 이미 끝난 매치를 출처로 연결하면 팀이 바로 채워진다.
- 전파가 이미 끝난 후속 매치의 팀을 바꾸게 되면 덮어쓰지 않고 409 `DOWNSTREAM_FINISHED`.
- 매치나 라운드를 지우면 그것을 가리키던 슬롯의 출처만 지우고 팀은 남긴다. `live_state.current_match`도 비우고 `live_state.updated`를 보낸다.
- `snapshot`과 `pong`은 seq를 올리지 않고 현재 값을 담는다. 브로드캐스트만 seq를 올린다.
- `/assets/` 아래의 없는 파일은 `index.html`이 아니라 404다(재배포 후 옛 청크 요청을 알아챌 수 있게). `index.html`은 `no-cache`, 자산은 immutable. 관리자 응답도 `Cache-Control: no-store`.
- 감사 로그는 로그인, 로그아웃, 비밀번호 재설정, 순서 변경, 시드, 대진 생성, 종료, 되돌리기도 기록한다. 비밀번호 해시는 기록하지 않는다.
- 입력 길이 제한: 아이디 `^[A-Za-z0-9_.-]{3,32}$`, 차량 번호 0–9999(2026-10-19에 차량 번호 삭제), 슬롯 수 1–16, 제목 200자, 짧은 글 200자, 긴 글 5000자, Markdown 10만 자, 공지 500자. 빈 선택 입력은 null.
- `backup`은 `<out>.partial`에 쓴 뒤 단일 파일 모드로 바꾸고 원자적으로 교체한다.
- `EVENT_TIMEZONE`은 시작할 때 검사한다.
- P2 `POST /api/admin/bracket/generate`(싱글 엘리미네이션, 2–32강, 3·4위전 선택)를 구현했다. `seed-demo`가 이것으로 8강 대진을 만든다.
- 프론트 타입 생성은 `--default-non-nullable false`로 한다. 기본값이 있는 요청 필드가 TS에서 필수로 잡히지 않게 하기 위해서다.

### 관리자 화면 구현 중 채운 결정
- 일정의 순서 변경은 같은 시작 시각의 항목끼리만 위/아래 버튼으로 한다. 일정은 시각순으로 정렬되고 `sort_order`는 같은 시각일 때만 쓰이기 때문이다(Instruction.md 6.2).
- 대진 결과 입력에서 순위를 고르면 그 순위를 갖고 있던 슬롯과 맞바꾸고, 마지막 슬롯은 남은 순위로 자동으로 채운다. 순위가 1부터 빠짐없이 매겨지게 하기 위해서다.
- 결과 되돌리기는 후속 매치가 이미 끝났으면 확인 전에 그 매치 이름을 보여 준다(서버의 `DOWNSTREAM_FINISHED`도 같은 문구로 보인다).
- 저장 중 세션이 만료되면(401) 로그인 화면으로 보내고, 로그인 후 원래 화면으로 돌아온다.
- 매치 순서는 라운드 사이 이동만 되고, 같은 라운드 안에서 순서를 바꾸는 기능은 아직 없다.

### 프론트엔드 빌드
- TypeScript `strict`를 켰다. create-vite 9 템플릿의 `tsconfig.app.json`에 빠져 있었다.
- Markdown 렌더러(react-markdown, remark-gfm)는 규칙 페이지와 관리자 미리보기에서만 쓰므로 지연 로딩한다. 첫 화면 JS가 586kB에서 430kB로 줄었다(gzip 182kB → 135kB).
- `ApiError`가 422 응답의 필드별 오류(`errors[]`)를 함께 담는다.

### 확인을 받아 닫은 질문 (2026-10-14)
- 히어로 원본 업스케일: 하지 않고 원본(1672px)을 유지한다(위 "히어로 이미지" 참고).
- 랩타임 입력 형식: 아이폰의 `inputmode="decimal"` 키패드에는 `:`가 없어 1분 이상의 랩타임(`1:02.345`)을 칠 수 없다는 문제를 물었다. 결과 입력은 항상 데스크톱에서 하므로 대체 형식(`1.02.345` 등)은 만들지 않고 Instruction.md 4.3의 입력 형식을 그대로 둔다.

### 규칙 ⇄ 서버 Markdown 문서 동기화
- 요청: 관리자 규칙 화면에 업로드 버튼을 두고, Markdown 파일을 올리면 바로 반영할 것. 웹에서 규칙을 고치면 서버 내부 Markdown에 반영할 것.
- 결정: 언어별 문서 하나(`RULES_DIR/rules.ko.md`, `rules.en.md`, 기본 `./data/rules`)를 둔다. 문서의 `## 제목` 하나가 `rule_sections` 한 행이다. DB가 화면의 기준이고, 문서는 DB가 바뀔 때마다 다시 쓰는 서버 쪽 사본이자 업로드 형식이다.
  - 웹 수정(추가, 수정, 삭제, 순서 변경, 공개 전환) → 커밋 후 두 문서를 원자적으로 다시 쓴다(임시 파일 + `os.replace`). 내용이 바뀌면 이전 파일을 `.bak`으로 남긴다. 파일 쓰기에 실패해도 API 응답은 성공으로 두고 오류 로그만 남긴다. 앱 시작과 `seed-demo` 때도 쓴다.
  - 업로드 `PUT /api/admin/rules/document {lang, markdown}`(관리자): 한국어는 순서대로 덮어쓰기·생성·삭제, 영어는 같은 순서 섹션의 영어 필드만 바꾼다(영어 제목이 한국어 제목과 같으면 빈 값으로 저장해 대체 표시를 유지). 한 트랜잭션, 감사 로그 1행(`import`), 이후 `content.updated(rules)` 방송.
  - 내려받기 `GET /api/admin/rules/document?lang=`. CLI `export-rules`, `import-rules --lang [--file]`.
  - 비공개 표시는 제목 아래 `<!-- hidden -->`(한국어 문서만).
- 함께 정한 규칙:
  - 규칙 본문에 `## `로 시작하는 줄(코드 블록 밖)을 쓸 수 없다(422, `###`을 쓰라고 안내). 문서로 내보냈다가 다시 올릴 때 섹션이 쪼개지지 않게 하기 위해서다. 이전에 저장된 본문의 `##`는 문서로 쓸 때 `###`로 바꾼다. 공개 페이지는 본문의 `###`을 h3(섹션 제목 h2 바로 아래)로 그린다.
  - 업로드가 바꾸지 않은 섹션은 version을 올리지 않는다. 빈 `##` 제목은 거부한다.
  - 영어 내용은 위치로 짝지어지므로, 한국어 문서 중간에 섹션을 넣으면 그 뒤의 영어가 한 칸씩 밀린다. 업로드 확인 창에서 이를 알린다.
  - UTF-8이 아닌 파일(EUC-KR 등)과 100만 자를 넘는 파일은 올리기 전에 거부한다. 의존성(`python-multipart`) 없이 JSON으로 보낸다.
- 대안: 문서를 기준으로 두고 DB를 캐시로 쓰는 방식. 섹션별 version과 공개 여부, 낙관적 잠금이 이미 DB에 있어 택하지 않았다.

### 규칙 문서 ZIP (문서 + 그림)
- 요청: Markdown 파일만 올리면 그림이 따라오지 않으니 ZIP을 받을 것. 문서에는 절대 경로가 들어 있을 것이고, ZIP을 받으면 자동으로 풀어서 적용할 것.
- 결정: `PUT /api/admin/rules/package?lang=` (본문 = ZIP 바이트, `application/zip`, `python-multipart` 없음). ZIP 안의 Markdown 하나(여러 개면 `rules.<lang>.md`)를 기존 문서 가져오기와 같은 규칙으로 적용하고, 문서가 쓰는 그림만 `RULES_DIR/files/<패키지 경로>`에 저장한다. 공개 주소는 `GET /api/rules/files/{path}`(png, jpg, gif, webp, avif만, `Cache-Control: no-cache`, `nosniff`). 내려받기 `GET /api/admin/rules/package?lang=`는 `rules.<lang>.md`와 그림을 같은 경로로 담아 그대로 다시 올릴 수 있다.
  - 본문에 저장하는 그림 주소는 `/` + 패키지 경로. 공백·`%`·`#`·`?`·괄호·`&`·따옴표 같은 ASCII 문자와 공백·제어 문자만 UTF-8 퍼센트 인코딩하고 한글은 그대로 둔다. 이미 올바른 URL 경로라 프론트는 `/api/rules/files` 뒤에 그대로 붙인다. 꺾쇠(`<…>`) 대신 이것을 고른 이유: 파일 이름의 `#`, `?`, `%`가 URL에서 깨지지 않고, 노션 내보내기도 같은 방식이다.
  - 주소 찾기: `file://`, 백슬래시, `%XX`, `?쿼리`·`#조각`을 정리한 뒤 상대 경로는 문서가 있는 폴더 기준, `/`로 시작하면 패키지 루트 기준으로 찾고, 없으면 경로 뒷부분이 가장 길게 같은 파일(대소문자만 다르면 하나뿐일 때), 그다음 이름이 같은 파일이 하나뿐일 때 그 파일을 쓴다. CommonMark로는 주소가 아닌 경우(공백이 든 경로, `image (1).png`)도 같은 줄의 `)`까지를 후보로 보고 찾으면 고친다. 찾지 못한 주소는 그대로 두고 경고(`warnings`)로 알린다. 가져오기는 실패시키지 않는다.
  - 모든 파일이 한 폴더 안에 있으면(폴더째 압축, 노션) 그 폴더가 패키지 루트다. ZIP 안에 ZIP 하나만 있으면 한 겹 열어 본다(노션의 Part-1.zip). 이름은 NFC로 맞추고, UTF-8 표시가 없는 이름은 UTF-8, 안 되면 CP949로 다시 읽는다.
  - 거부(4xx, 아무것도 바꾸지 않음): 요청 50MB 초과(413 `PAYLOAD_TOO_LARGE`), 압축을 푼 크기 200MB 초과, 항목 1,000개 초과, `..`·절대 경로·드라이브 문자, 심볼릭 링크, 암호, Markdown 없음/여럿, UTF-8 아닌 문서. `__MACOSX/`, `._*`, `.DS_Store`, `Thumbs.db`, `desktop.ini`는 무시한다. SVG는 같은 origin에서 스크립트를 실행할 수 있어 받지 않는다.
  - 그림은 임시 폴더(`RULES_DIR/.package-*`)에 다 푼 뒤 제자리로 옮기고 커밋한다. 커밋 후 문서 파일을 다시 쓰고, 어느 섹션 본문(ko, en)도 쓰지 않는 그림을 지운다. 정리는 가져오기(ZIP, Markdown, CLI) 때만 하고 웹 편집 때는 하지 않는다(실수로 지운 주소를 되돌려도 그림이 남아 있게).
  - 한 언어의 ZIP이 다른 언어 본문이 쓰는 그림을 바꾸지 않는다. 노션은 그림 이름을 `image.png`, `image 1.png`처럼 붙여 두 언어 ZIP의 이름이 겹치기 쉽다. 같은 경로에 내용이 다른 그림이 있고 다른 언어가 쓰고 있으면 새 그림을 `image-<sha256 8자리>.png`로 저장하고 경고로 알린다.
  - Markdown만 올리면(`PUT /rules/document`, CLI `.md`) 그림 주소를 이미 저장된 그림으로 찾는다. 노션식 여러 줄 표 칸은 두 경로 모두 `<br>`로 잇는다(코드 블록 안은 그대로).
  - 응답 `RulesImportResult`에 `assets`(문서가 쓰는 그림 수)와 `warnings`를 더했다. CLI `import-rules --file`은 `.zip`도 받는다.
- 함께 정한 규칙: 공개 그림은 경로만 알면 받을 수 있다(비공개 섹션의 그림도). 대회 규칙 그림이라 따로 막지 않는다. 리버스 프록시의 본문 한도를 50MB로 올려야 한다(README).
- 관리자 본문 편집기: 사용자 요청(2026-10-13)으로 입력창과 미리보기를 나란히 둔다. 한 번에 한 언어(한국어/English 전환), 1024px 이상은 같은 높이 두 칸(`min(70vh, 720px)`, 미리보기 스크롤은 입력창 스크롤 비율을 따른다), 좁은 화면은 [수정]/[미리보기] 전환.

- 이유: 사용자 피드백("큰 것은 조금 줄이고 너무 작은 것은 조금 키워 평준화"). Design.md 5장의 "히어로 제목과 본문의 크기 대비를 크게"와 다르다.

### 규칙 페이지: Markdown 뷰어
- 조사(2026-10-13, npm): @uiw/react-markdown-preview(주간 약 98만, MIT, React ≥16.8, react-markdown + remark-gfm 기반 GitHub 스타일 뷰어), md-editor-rt의 MdPreview(약 7천, 미리보기에도 CodeMirror 의존), Toast UI Editor Viewer(2023년 이후 갱신 없음, React 17까지), github-markdown-css(CSS만).
- 결정: `@uiw/react-markdown-preview`(코드 하이라이트를 뺀 `nohighlight` 진입점)를 쓴다. 이미 쓰던 react-markdown·remark-gfm 위에 얹힌 것이라 바꾸는 범위가 작다. GitHub 색 변수는 `Markdown.module.css`에서 토큰으로 바꾼다.
- HTML: 뷰어는 raw HTML(표 칸의 `<br>` 등)을 그린다. 대신 `rehype-sanitize`(GitHub 허용 목록 + 알림 블록 클래스)를 rehype-raw **뒤에** 둔다. 라이브러리가 rehype-raw를 사용자 플러그인 뒤에 붙이므로 `pluginsFilter`로 순서를 잡았다. Instruction.md 5.3의 "raw HTML은 렌더링하지 않는다"와 다르다. 위험한 태그와 속성은 지운다.
- 물결표: GFM의 `~한 개` 취소선을 끈다(`singleTilde: false`). 시간표의 `10:00~13:00`이 취소선이 되던 문제. `~~취소~~`는 그대로 된다.
- 표 칸 줄바꿈: Notion에서 내보낸 표는 칸 안에 줄바꿈이 그대로 들어가 표가 끊긴다. 화면에서 `|`로 끝나지 않는 행을 다음 줄들과 `<br>`로 이어 붙인다(`normalizeTables.ts`). 서버도 업로드 때 같은 정리를 한다.
- 제목: 섹션 제목이 h2, 본문 `#`이 h3(목차 2단계), `###`이 h4다.
- 목차: 렌더된 문서에서 섹션 제목과 본문 `#` 제목을 모아 두 단계로 보여 주고, 지금 읽는 위치를 표시한다. 좁은 화면에서는 위쪽에 접을 수 있다.
- 폭: 사이트 전체의 컨테이너를 1280px → 1440px 하나로 통일했다(헤더·푸터·모든 페이지 공통). 규칙 본문은 1440px 화면에서 1040px(이전 700px)이고 좌우 여백이 같다. 처음에는 규칙 페이지만 오른쪽으로 넓히거나 더 넓은 전용 폭을 썼는데, 좌우 비대칭과 "규칙 페이지를 드나들 때 헤더가 좌우로 움직인다"는 피드백으로 하나의 폭으로 정리했다.
- 그림: 본문의 그림 경로(`/images/a.png` 또는 `a.png`)는 `/api/rules/files/...`로 바꿔 그린다(`ruleFiles.ts`).
- 번들: 뷰어는 규칙 페이지와 관리자 미리보기에서만 따로 불러온다(gzip 약 120kB). 첫 화면 JS는 그대로다.

### 모니터링: 예선·본선 탭
- 결정: 모니터링 페이지의 예선 리더보드와 본선 대진을 위아래로 잇지 않고 탭으로 나눈다(사용자 피드백: 본선을 보려면 계속 스크롤해야 한다). 탭은 표준 탭 구조(role=tab/tabpanel, ←·→·Home·End)이고, 고른 탭은 주소(`?tab=qualifying|bracket`)에 남아 새로고침·공유해도 유지된다.
- 처음 열 때는 진행 단계를 따른다(본선 진행 중·종료 후에는 본선 탭). 일반 화면은 그 뒤로 고정해서, 보는 중에 운영진이 단계를 바꿔도 화면이 저절로 넘어가지 않는다. 프로젝터용 큰 화면(`?display=1`)은 계속 진행 단계를 따라간다.
- 진행 중인 쪽 탭에 "진행 중" 표시(점 + 문구)를 붙인다. 큰 화면 전환 링크는 탭 줄 오른쪽 끝으로 옮기고, 휴대폰(768px 미만)에서는 숨긴다. 영어 탭 이름은 좁은 화면에 들어가도록 "Qualifying" / "Finals"로 짧게 쓴다.

### 모니터링 탭 애니메이션
- 결정: 탭을 옮기면 밑줄이 고른 탭으로 미끄러지고(transform·width 전환), 새 내용이 옮긴 방향에서 살짝 밀려 들어오며 나타난다(0.24초, `--dur-tab`). 사용자가 탭을 고를 때만 움직이고, 처음 열 때와 실시간 갱신 때는 움직이지 않는다. 모션 감소 설정에서는 바로 바뀐다.
- 이유: 사용자 요청(2026-10-14). Design.md 6.6의 "사용자 행동 없이 저절로 움직이는 효과" 제한에는 해당하지 않는다(사용자 행동에 대한 반응).

### 모니터링 탭 모양: 버튼형, 고른 탭은 옅은 바탕
- 결정: 예선·본선 탭을 글자 + 밑줄에서 테두리 있는 버튼 모양으로 바꿨다. 마우스를 올리면 바탕(`--paper-2`)과 테두리가 진해지고, 누르는 동안 1px 눌려 들어간다. 고른 탭은 옅은 하늘색 바탕(`--neon-tint`)에 진한 테두리와 두꺼운 아랫선(`--neon-ink`)을 둔다. 이 바탕이 탭을 옮길 때 미끄러져 간다(앞의 밑줄 애니메이션을 대신한다). 큰 화면 모드에서는 어두운 면 토큰으로 바뀐다.
- "진행 중" 표시는 흰 바탕 칩으로 둔다. 고른 탭의 하늘색 바탕 위에서 주황 글자(`--signal-ink`)의 대비가 4.46:1로 기준(4.5:1)에 조금 못 미치기 때문이다. 흰 바탕에서는 4.91:1이다.
- 이유: 사용자 피드백(2026-10-14): 탭을 누를 수 있는지 잘 보이지 않고, 지금 어떤 탭을 골랐는지 눈에 띄지 않는다.

### 큰 화면은 언제나 진행 단계를 따라간다
- 문제: 일반 모니터링 화면에서 "큰 화면" 링크를 누르면 보고 있던 탭(`?tab=`)이 주소에 함께 넘어가 큰 화면이 그 탭에 고정됐다. 프로젝터 화면이 진행 단계를 따라 바뀌지 않았다(설명서를 만들다 발견).
- 결정:
  - "큰 화면" 링크는 탭을 넘기지 않고 `/live?display=1`로 간다. 큰 화면은 주소의 `?tab=`을 보지 않는다(예전에 저장해 둔 `display=1&tab=…` 주소도 진행 단계를 따른다).
  - 큰 화면에서 탭을 직접 누르면 그 탭을 보여 주되 주소에 남기지 않는다. 진행 단계 탭(예선 → 예선 리더보드, 본선이나 종료 후 대진이 있으면 → 본선 대진)이 바뀌는 순간 버리고 다시 진행 단계를 따라간다. 단계가 되돌아와도 손으로 고른 탭은 되살아나지 않는다(`features/live/liveTab.ts`).
  - "큰 화면 끄기"는 보던 탭을 `?tab=`으로 넘겨 일반 화면에서 그대로 연다. 일반 화면은 지금처럼 처음 연 단계의 탭에 고정된다.
  - 진행 단계에 따라 탭이 저절로 바뀔 때는 내용이 옆에서 들어오는 움직임을 쓰지 않는다(사용자가 고를 때만). 탭 내용의 움직임 방향은 움직임이 끝나면 지운다.
- 이유: 사용자 요청(2026-10-14).

### 공개 페이지 열고 닫기 (일정·규칙·모니터링)
- 결정: 관리자 화면 "사이트 설정"의 "페이지 공개"에서 일정, 규칙, 모니터링 페이지를 각각 열고 닫는다. 닫힌 페이지는 메뉴에 그대로 남고(사용자 선택), 들어가면 내용 대신 "준비 중" 안내와 문구가 보인다. 문구는 관리자가 페이지마다 한국어·영어로 쓸 수 있고(최대 200자, 예: "작업 중입니다", "11월 1일에 공개합니다"), 비우면 페이지별 기본 문구를 쓴다. 영어 문구가 비면 영어 화면에도 한국어 문구를 보여 준다(다른 입력 칸과 같은 규칙).
- 저장: 설정 키-값 표(`site_settings`)에 `page_<페이지>_open`("0"이면 닫힘, 없으면 열림), `page_<페이지>_note_ko/en`으로 둔다. DB 구조는 바뀌지 않는다. 신청 설정과 덮어쓰지 않도록 따로 저장한다(`PUT /api/admin/settings/pages`, 세 페이지를 모두 보낸다). 변경 이력에 "사이트 설정 · pages"로 남는다.
- 반영: 저장하면 `content.updated(settings)`가 나가 보고 있던 공개 화면도 새로고침 없이 바뀐다.
- 서버: 닫힌 일정·규칙은 공개 API(`/api/schedule`, `/api/rules`, `/api/rules/files/...`)도 404 `PAGE_CLOSED`로 내주지 않는다(작업 중인 내용이 새지 않게). 모니터링은 실시간 연결이 기록을 계속 보내므로 화면만 닫는다. 관리자 API는 그대로 쓸 수 있다.
- 첫 화면: 일정이 닫히면 "다음 일정"을, 모니터링이 닫히면 "실시간 기록 보기" 버튼을 숨긴다. 프로젝터 큰 화면도 닫힘 안내를 어두운 화면으로 보인다.
- 실제 사이트: 사용자 요청(2026-10-16)으로 일정·규칙·모니터링을 모두 닫아 두었다(기본 문구). 서버 명령으로 바꿔 변경 이력에는 "서버 명령으로 바뀜"으로 남는다. 신청 폼 주소와 접수 마감(10월 23일, 날짜만)도 같은 방법으로 넣었다.
- 이유: 사용자 요청(2026-10-16).

### 헤더 메뉴 이동 애니메이션
- 결정: 헤더 메뉴의 밑줄도 모니터링 탭처럼 고른 메뉴로 미끄러진다. 메뉴에 있는 페이지끼리 옮기면 새 페이지가 메뉴 순서 방향(오른쪽 메뉴면 오른쪽, 왼쪽 메뉴면 왼쪽)에서 살짝 밀려 들어오며 나타난다(0.24초). 헤더 메뉴뿐 아니라 본문 링크나 뒤로 가기로 옮길 때도 같은 규칙을 따른다. 처음 열 때, 메뉴에 없는 주소(없는 페이지)를 오갈 때, 같은 페이지 안(`?tab=` 바꾸기)에서는 움직이지 않는다.
- 첫 화면 히어로처럼 어두운 면(`data-surface="dark"`)은 움직이지 않는다. 흰 바탕 위에서 옅어졌다 짙어지면 번쩍여 보이기 때문이다. 히어로는 원래 있던 등장 연출(글자 나타남, 선 긋기)만 보인다.
- 휴대폰(768px 미만)의 펼침 메뉴는 칸마다 밑줄이 있으므로 미끄러지는 밑줄을 쓰지 않는다.
- 모션 감소 설정에서는 페이지·탭 내용 애니메이션을 아예 돌리지 않는다. 전역 규칙처럼 시간을 0.01ms로 줄이기만 하면 첫 프레임에 빈(투명한) 화면이 한 번 비친다.
- 이유: 사용자 요청(2026-10-14). 사용자 행동에 대한 반응이라 Design.md 6.6의 제한에 해당하지 않는다.

### 스크롤바 자리 항상 확보
- 결정: `html`에 `scrollbar-gutter: stable`을 둔다. 내용이 짧아 스크롤바가 없는 페이지(신청)와 스크롤바가 있는 페이지를 오갈 때 화면 폭이 15px 바뀌어 가운데 정렬된 헤더·본문이 좌우로 밀리던 문제를 없앤다(1920px 화면에서 로고 위치가 281px↔288px로 바뀌던 것을 실측으로 확인하고 고쳤다). 짧은 페이지에서는 오른쪽에 스크롤바 폭만큼 빈 자리가 남는다.
- 프로젝터용 큰 화면(`/live?display=1`)은 페이지를 오가지 않고 어두운 바탕이라 빈 자리가 밝은 띠로 보이므로 이 설정을 끈다.
- 휴대폰처럼 스크롤바가 화면 위에 겹쳐 그려지는 환경에서는 효과가 없다(원래 폭이 바뀌지 않는다).

## 2026-10-19 — 팀 ID 기준, 랭킹, 모니터링 관리 주소

Instruction.md 의 차량 번호(5.4 모니터링, 5.6 관리자, 6장 teams 표, 7장 정렬)와 `/admin/live`·`/admin/qualifying` 화면은 아래 결정으로 바뀐다.

### 팀은 ID 와 이름으로 구분 (차량 번호 삭제)
- 결정: `teams.car_number` 를 지우고 팀 이름(`name_ko`)을 겹칠 수 없게 했다(대소문자 무시, 겹치면 422 `DUPLICATE`). 모든 표의 기준은 팀 ID 이며, 예선 기록·랭킹·대진 슬롯이 모두 팀 ID 로 이어진다. 관리자 화면은 팀을 "#ID 팀이름"으로 보이고, 팀 찾기는 이름·소속·ID 로 한다. 공개 화면에서는 차량 번호 칸을 뺐다. 기록 없는 팀은 팀 ID 순으로 아래에 둔다.
- 마이그레이션 `0002`: 차량 번호를 지우고 팀 이름 유일 제약을 건다. 되돌리면 차량 번호를 팀 ID 로 채운다.
- 이유: 사용자 요청(2026-10-19). 작년 팀 목록(엑셀)처럼 팀을 이름으로 구분한다. 작년 팀 이름은 실제 데이터라 저장소·데모에 넣지 않았다.

### 랭킹 표와 본선 시드
- 결정: 새 표 `team_rankings(team_id PK → teams.id, rank 유일)`. 운영진이 순위를 직접 정하고(사용자 선택), "예선 기록 순서로 채우기"는 편의 기능일 뿐 저장해야 반영된다. 저장은 통째로 바꾸며(`PUT /api/admin/ranking`, 1위부터 팀 ID 목록), 같은 팀 두 번·없는 팀·비활성 팀은 422. 빈 목록이면 랭킹을 비운다.
- 본선의 "예선 N위" 슬롯은 이제 예선 리더보드가 아니라 저장된 랭킹 N위로 채운다(`POST /api/admin/bracket/seed-from-ranking`). 랭킹을 바꿔도 시드는 "시드 채우기"를 눌러야 바뀐다(종료된 매치는 그대로).

### 모니터링 관리: 관리자 화면에서 분리, 로그인 없는 주소
- 결정: 대회 당일 입력(진행 상태, 예선 기록, 랭킹·시드, 본선 결과)은 관리자 화면이 아니라 `/monitoring-admin` 한 화면에서 한다. 번호 붙은 큰 탭 네 개(`?tab=live|qualifying|ranking|results`). 예전 `/admin/live`, `/admin/qualifying` 주소는 이 화면으로 넘긴다. 대진 모양 편집(라운드·매치·슬롯)은 관리자 화면 "본선 대진"에 남는다.
- 들어오는 방법: ① `/monitoring-admin?pw=<비밀 값>` — 로그인 없이. 화면이 값을 `X-Monitor-Key` 헤더로 매 요청에 보내고, 서버는 `site_settings.monitor_key` 와 상수 시간 비교한다. 세션을 만들지 않는다. ② 로그인한 운영진(관리자·심판)은 값 없이도 연다.
- 주소로 열 수 있는 API 는 모니터링 관리에 필요한 것만이다(기록 입력·수정·무효, 진행 상태, 랭킹, 시드 채우기, 결과 입력·되돌리기, 대진 조회). 팀·일정·규칙·설정·계정 API 는 열리지 않는다.
- 주소로 남긴 기록의 작성자는 시스템 계정 `monitoring`(로그인 불가, 계정 목록에 안 보임)이고, 화면에는 "모니터링 관리 (주소로 접속)"으로 보인다.
- 비밀 값: 관리자 "사이트 설정 → 모니터링 관리 주소"나 서버 명령 `monitor-key --generate | --value <값> | --off` 로 정한다(영문·숫자·`-`·`_` 6~64자, 무작위 16자 권장). 바꾸면 예전 주소는 바로 막히고, 끄면 로그인한 운영진만 연다. 처음에는 꺼져 있다. 변경 이력에는 값 자체를 남기지 않는다(`{"set": true}`만). 틀린 값은 같은 IP 에서 10번이면 10분 막힌다(로그인 제한과 같은 방식).
- 주소에 값이 들어가므로: 검색 엔진 색인 금지(`noindex`), 다른 사이트로 나갈 때 주소를 넘기지 않음(`no-referrer`). 서버 접속 기록(엣지 access log)에는 주소가 남는다. 값이 새었으면 바로 바꾼다.
- 진행 중 매치를 고르면 그 매치 상태가 "진행 중"이 되고, 다른 매치로 바꾸거나 비우면 이전 매치는 "예정"으로 돌아간다(종료된 매치는 건드리지 않는다).
- 이유: 사용자 요청(2026-10-19). 심판 계정은 남겨 두고(사용자 선택), 심판은 관리자 화면에서 대시보드와 모니터링 관리 바로가기만 본다.

## 2026-10-19 — 참가 팀 15팀, 기권 처리, 부전승, 점검에서 나온 버그

### 참가 팀은 최대 15팀
- 결정: 활성(참가) 팀은 최대 15팀(`MAX_ACTIVE_TEAMS`). 16번째를 추가하거나 비활성 팀을 다시 활성화하면 409 `TEAM_LIMIT`. 비활성 팀은 세지 않으므로 비활성으로 등록해 두는 것은 된다. 팀 화면에 "참가 N / 최대 15팀"을 보이고, 가득 차면 '팀 추가'와 '다시 활성화'를 막는다. 랭킹도 15팀까지, 본선 자동 생성은 16강까지(32강 제거).
- 이유: 사용자 요청(2026-10-19).

### 비활성화 = 기권: 예선 랭킹·본선에 남지 않는다
- 결정: 팀을 비활성화하면 같은 저장 안에서 ① 랭킹에서 빼고 아래 순위를 한 칸씩 당기고 ② 끝나지 않은 매치 칸에서 빼고 ③ 트랙 위 팀이면 비운다(`services/teams.py`). 예선 기록과 끝난 매치 결과는 기록으로 남는다. 다시 활성화해도 랭킹·대진 칸은 되돌리지 않는다.
- 끝난 매치에서 기권한 팀은 다음 매치로 올리지 않는다. 끝난 매치를 되돌리면 기권한 팀은 그 매치 칸에서 빠진다. 결과 저장은 비활성 팀이나 같은 팀 두 번이 든 매치를 거절한다. 랭킹 조회는 활성 팀만 보인다.
- 시드 채우기는 이미 다른 칸(끝난 매치, 직접 지정, 앞 매치 결과)에 있는 팀을 다시 넣지 않는다. 기권으로 랭킹이 당겨진 뒤 다시 채워도 이미 진 팀이 다른 매치에 들어가지 않는다. 바뀐 것이 없으면 변경 이력을 남기지 않는다.
- 랭킹이 바뀌면(저장, 기권) `content.updated(ranking)`을 보내 열려 있는 모니터링 관리 화면이 다시 가져온다. 고치던 중이면 "다른 운영진이 바꿨다" 안내와 최신 값 불러오기를 보인다(덮어쓰지 않게).

### 부전승 (빈 칸이 있는 매치)
- 결정: 예선에서 탈락이 없어 본선이 최대 16강이고 팀이 15팀 이하이므로 빈 칸이 생긴다. 팀이 하나 이상 있고, 빈 칸이 앞으로도 채워지지 않을 칸이면 팀이 있는 칸만 순위를 매겨 끝낼 수 있다(빈 칸은 결과 없음 = 부전승). 혼자면 1위로 올라간다.
- "앞으로도 채워지지 않을 칸": 앞 매치가 끝난 출처 칸, 랭킹에 그 순위 팀이 없거나 그 팀이 이미 다른 칸에 있는 시드 칸, 직접 지정 칸을 비워 둔 것. 시드를 아직 안 채웠거나 앞 매치가 안 끝났으면 거절한다(일찍 끝내는 실수를 막는다).
- 본선 모양은 관리자 "본선 대진"에서 자유롭게 바꾼다(라운드·매치·칸 수·칸 종류). 자동 생성(2·4·8·16강)은 표준 시드 배치라 팀이 모자라면 상위 시드가 부전승이 된다.

### 점검에서 고친 것 (2026-10-19, 백엔드·프론트 검토)
- 신청 설정을 저장할 때 변경 이력에 모니터링 관리 비밀 값이 그대로 남던 것을 고쳤다(페이지 공개 값도 따로 남기므로 뺀다).
- `FORWARDED_ALLOW_IPS="*"`이면 방문자가 `X-Forwarded-For`를 꾸며 시도 제한을 피하거나 남의 IP를 막을 수 있었다. 엣지 네트워크 대역만 믿도록 바꿨다(기계 전용 설정). 시도 제한 기록은 많아지면 오래된 것을 지운다.
- `monitoring` 아이디는 사람이 만들 수 없다(시스템 계정과 섞이지 않게).
- 칸의 출처를 끊거나 시드 순위를 바꾸면 예전 팀을 남기지 않는다. 진행 중 매치를 되돌리면 '진행 중'으로 둔다.
- 모니터링 관리: 쓰는 중에 주소가 바뀌거나 로그인이 끝나면 화면을 내리고 더 요청하지 않는다(재시도가 시도 제한을 다 써 버리지 않게). 4xx 오류는 자동으로 다시 시도하지 않는다. 로그인 링크는 로그인 뒤 모니터링 관리로 돌아온다(비밀 값은 넘기지 않는다).
- 랭킹 편집: 화면에 보이는 목록 기준으로 순서를 바꾸고, 저장하면 '저장됨'을 보인다. 저장된 순위가 1위부터 이어지지 않으면 다시 저장하기 전까지 시드 채우기를 막는다. 랭킹이 비어 있으면 시드 채우기를 막는다. 휴대폰 폭에서 버튼이 다음 줄로 내려가게 했다.
- 표 안의 확인 창 글이 줄바꿈되지 않던 것, 확인 창 제목 연결(aria-labelledby), 저장 중 Esc 로 닫히던 것, 모르는 실시간 자료가 오면 모든 쿼리를 다시 가져오던 것, 공개 모니터링의 첫 탭이 대진을 받기 전에 정해지던 것을 고쳤다.

## 2026-10-19 — 미리보기와 게시

### 일정·규칙·사이트 설정은 게시해야 공개된다
- 결정: 관리자 화면에서 고친 일정, 규칙, 사이트 설정(참가 신청 폼·접수 기간, 일정·규칙·모니터링 페이지 열고 닫기와 안내 문구)은 초안이다. 공개 사이트는 '게시'한 공개본(`published_content`, 항목마다 공개 화면에 보일 모습을 통째로 저장)을 내준다. 게시는 관리자만 한다(`POST /api/admin/publish/{schedule|rules|settings}`, 서버 명령 `publish --resource …|all`).
- 바로 적용하는 것: 대회 기록(예선·랭킹·본선·진행 상태)과 팀, 계정, 모니터링 관리 비밀 값. 실시간이어야 하거나 보안 설정이라 게시를 거치지 않는다.
- 미리보기: 관리자 화면의 '미리보기 ↗'는 공개 화면을 `?preview=1`로 새 탭에 연다. 관리자로 로그인한 탭에서만 초안(`/api/admin/preview/…`)을 보이고, 맨 위 주황 막대에 게시하지 않은 변경과 게시 버튼, '닫힌 페이지도 실제 화면으로 보기', '미리보기 끝내기'를 둔다. 미리보기는 그 탭에만 유지된다(sessionStorage). 관리자가 아니면 막대가 로그인을 안내하고 공개본을 보인다.
- 닫힌 페이지: 미리보기에서 '닫힌 페이지도 실제 화면으로 보기'를 켜면 닫힌 일정·규칙·모니터링도 내용을 보인다(공개 전에 실제 화면 확인). 규칙 그림도 관리자 전용 주소(`/api/admin/preview/rules/files/…`)로 보여, 규칙 페이지가 닫혀 있어도 미리보기와 관리자 규칙 편집에서 그림이 보인다.
- 게시 상태: 일정·규칙·사이트 설정 화면 맨 위에 '게시 전 변경 있음 / 공개 사이트와 같음', 마지막 게시 시각·계정, 미리보기·게시 버튼을 둔다. 대시보드 '공개 사이트' 상자에 게시 대기 항목을 보인다. 변경 이력에 "게시"로 남는다(규칙 본문은 제목만).
- 처음 배포: 서버가 시작할 때 공개본이 없으면 그때 내용으로 만든다. 그래서 배포해도 공개 사이트는 바뀌지 않고, 그 뒤로 고친 것부터 게시가 필요하다. 데모 데이터(`seed-demo`)는 넣은 뒤 모두 게시한다.
- 초안 버리기(게시본으로 되돌리기)는 만들지 않았다. 공개본은 공개 화면용 모습만 담고 있어 관리자 자료(비공개 항목, 버전)를 되살릴 수 없기 때문이다.
- 이유: 사용자 요청(2026-10-19): 화면을 바로 올리지 말고 미리보기로 확인한 뒤 확인을 누르면 올라가게.

## 2026-10-23 — 검색엔진 노출

### 서버가 검색엔진용 HTML 을 만든다
- 결정: 공개 화면은 브라우저가 그리는 SPA 라 서버가 내주는 HTML 이 비어 있었다(구글은 렌더링해서 읽지만 느리고, 네이버는 잘 못 읽는다). index.html 을 내줄 때 서버가 페이지마다 제목, 설명, 대표 그림(OG·트위터 카드), 대표 주소(canonical), 첫 화면에는 구글 행사 정보용 구조화 데이터(schema.org Event: 일시·장소·주최)를 넣는다. `#root` 안에는 게시한 내용으로 만든 본문(일정 목록, 규칙 제목과 앞부분, 신청 정보 등)을 넣고, React 가 그리면서 바꾼다.
- 미리 넣은 본문은 느린 휴대폰에서 화면이 그려지기 전 약 0.3초 보인다(데스크톱은 약 0.04초, 측정). 그 전에는 빈 흰 화면이었다. 바뀌는 순간이 튀지 않게 실제 화면처럼 위쪽은 어두운 막대, 첫 화면은 어두운 히어로 영역으로 맞췄다. 내용은 실제 화면과 같은 정보라 숨기지 않는다(숨긴 글은 검색엔진이 스팸으로 볼 수 있다).
- 관리자 화면·모니터링 관리는 서버에서도 `noindex`. 없는 주소는 앱의 '페이지 없음' 화면을 내되 상태는 404(검색엔진이 없는 페이지를 색인하지 않게).
- 사이트맵은 `PUBLIC_URL` 을 정했을 때만 내고, 닫아 게시한 페이지는 넣지 않는다. 엣지가 경로 앞부분(/roboracer)을 떼고 넘겨 앱이 자기 주소를 모르므로 공개 주소는 설정으로 받는다(개인 주소는 기계 전용 override 에만).
- robots.txt 는 호스트 맨 앞(엣지, 다른 앱과 공유)에만 의미가 있어 만들지 않았다. 없으면(404) 모두 허용으로 본다. 사이트맵은 서치 콘솔에 직접 제출한다.

## 2026-10-23 — 규칙의 장(# 큰 제목), 일정 24:00

### 규칙 섹션에 장(#)과 절(##) 단계
- 문제(사용자 피드백): 규칙 문서는 `# 1. 개요`(장) → `## 1.1 …`(절) → `###`(소제목) 세 단계인데, 사이트는 `##` 로만 섹션을 나눠 `#` 장 제목이 앞 섹션 본문 끝에 묻혀 있었다. 관리자 목록에 장 제목이 보이지 않았고, 예를 들어 '1. 개요' 장의 내용이 '※ 공지 사항' 섹션 본문 안에 들어 있었다.
- 결정: 규칙 섹션에 단계(`level`: 1=장, 2=절)를 둔다(마이그레이션 0004). 문서의 `# 제목` 줄은 장, `## 제목` 줄은 절을 시작한다. 맨 위 `# 대회 규칙` 한 줄(또는 아래에 글 없이 바로 다음 제목이 오는 첫 `#` 줄)은 문서 제목으로 보고 건너뛴다. 섹션 본문에는 `#`·`##` 제목 줄을 쓸 수 없다(소제목은 ###).
- 공개 규칙 페이지: 장은 큰 제목(왼쪽 선, 옅은 바탕), 그 아래 절은 한 단계 아래 제목. 목차도 장 → 절로 들여 쓴다. 첫 장보다 앞의 절(공지 등)과 장이 없는 문서는 예전과 같다. 본문이 없는 장은 제목만 보인다.
- 관리자 규칙 목록: 장은 '장' 표시와 옅은 바탕의 묶음 머리, 장 아래 절은 들여 쓴다. 수정 화면에서 '단계(장/절)'를 고른다.
- 영어 문서는 한국어 문서와 장·절 구조가 같아야 한다(자리가 다르면 몇 번째 섹션이 장/절이어야 하는지 알려 주고 거절).
- 실제 규칙: 배포 뒤 DB 의 한국어 본문을 그대로 이어 붙인 문서를 새 형식으로 다시 가져와 30개 섹션을 장 9개 + 절·공지 30개(39개)로 나눴다. 내용은 같고 구조만 바뀌므로 게시까지 했다(나누기 전에 게시하지 않은 규칙 초안은 없었다).
- 게시 비교: 예전에 게시한 공개본에 새 칸(level)이 없어도 지금 형식으로 읽어(기본값) 비교한다. 칸이 늘었다고 '게시 전 변경'으로 보이지 않게. 시각도 UTC 로 맞춰 적는다(같은 시각이 +09:00 과 Z 로 달리 적혀 변경으로 보이던 것).

- 순위결정전: 앞 경기 패자만 받는 라운드(3·4위전, 5~8위전)는 본 대진 아래 '순위결정전' 줄에 따로 둔다(카드 머리 'Race 10 · 3·4위전'). 프로젝터 큰 화면은 1920×1080 한 화면에 다 보이게 결승 오른쪽 열에 쌓는다. 처음처럼 6개 라운드를 한 줄로 두면 결승 칸이 오른쪽에서 잘렸다.
- 경기 블록: 바탕과 겹치지 않게 블록 안은 한 단계 짙은 면(--paper-2), 머리 줄은 --line. 큰 화면에서는 같은 토큰이 짙은 남색이 된다.
- 화살표: 승자가 올라가는 칸마다 꺾인 화살표(SVG, 블록의 실제 위치를 재서 그린다). 앞 경기가 끝나 진출이 정해지면 청록 실선, 아직이면 회색 점선. 화살표 자리를 위해 열 사이를 48px로 넓혔다.
- 매치 안 결과: 두 팀 경기는 '1위/2위' 대신 '승/패', 칸 이름도 'Race 2 승'·'Race 7 패'. '1위'는 대회 순위와 헷갈리고, '승자/패자'는 공격적으로 보인다는 사용자 의견. 여러 팀이 함께 달리는 매치만 'N위'로 둔다. 영어는 Win/Loss, 'Race 2 W'·'Race 7 L'. 운영 콘솔·관리자 화면도 같다.
- 결과 메모가 길면 팀 이름을 글자 중간에서 쪼개지 않고 메모를 다음 줄로 내린다.

### 모니터링 리허설
- 실제 DB 복사본(10팀, 같은 대진)을 로컬에 따로 띄우고 Playwright로 운영 콘솔을 끝까지 조작했다. 예선 기록 21건 입력·무효·수정 → 랭킹·시드 → 본선 12경기(결과 되돌리기, 두 운영진 동시 입력, 휴식 공지, 결승 판 공지)까지 31개 항목이 모두 통과했다. 공개 화면 반영은 중앙값 0.06초였다. 공개 화면의 실시간 연결이 끊긴 동안 들어온 기록도 다시 붙으면 따라잡는다.
- 실제 사이트에는 테스트 기록을 넣지 않았다. 모니터링 페이지를 닫아도 공개 API와 실시간 연결로는 기록이 나가기 때문이다.

### 예선 순위를 규칙대로 자동 계산 (2026-10-26, 사용자 결정)
- 문제: 공개 예선 리더보드가 모든 랩 중 최고 랩타임 순이라 규칙 4.7(FA → 통과한 미션 수 → 마지막 미션 기록 → 차량 검사 순서)과 달랐고, 콘솔에 미션·FA를 적을 곳이 없었다.
- 결정(사용자가 고름: 모두 추천안):
  - 콘솔 입력은 랩마다. 트랙 위 팀이 자동으로 골라지고, 랩이 끝날 때마다 '유효 랩'/'무효 랩'을 누른다. Q3 의 유효 랩은 랩타임이 필요하다. 빠르게 누르도록 확인 창 대신 '되돌리기'(입력 취소)를 둔다.
  - 미션(Q1·Q2·Q3)은 무충돌 연속 3랩이 되면 저절로 다음으로 넘어간다. 운영진이 미션을 직접 고르지 않으면 서버가 저장하는 순간의 진행으로 정한다(화면이 갱신되기 전에 눌러도 맞게).
  - 공개 리더보드는 규칙 4.7 예시 표 모양: 순위, 팀, 소속, FA(O/X), Q3 최속 랩, Q2 완료 랩, Q1 완료 랩. 트랙 위 팀에는 '● 진행 중 · Q2 연속 2랩'. 랩 기록이 없는 팀은 순위 없이 맨 아래.
  - 동률은 콘솔 랭킹 탭의 '차량 검사 순서'에서 '검사 완료'를 누른 순서. 아직 검사 전인 팀은 뒤로.
  - 판정: 'FA 달성 불가'(한 번)와 '최종 예선 순위 1단계 강등'(여러 번)을 사유와 함께 기록하고, 잘못 넣으면 취소한다. 강등은 계산된 순위에서 아래 팀부터 옮겨, 판정받은 팀이 저마다 그만큼 내려가게 한다. 공개 표에는 순위 옆 ▼1.
- 데이터: 랩에 mission, 상태는 valid/invalid/void(입력 취소). 팀에 inspected_at, 판정 표 qualifying_events (마이그레이션 0005, 예전 DNF·실격은 무효 랩). 실제 DB 에는 아직 랩 기록이 없다.
- 랭킹 탭의 '예선 기록 순서로 채우기'는 '예선 자동 순위로 채우기'가 된다. 본선 시드는 여전히 저장한 랭킹으로 채운다(운영진이 확인하고 고칠 수 있게).
- 확인: 운영 DB 복사본에서 새 콘솔로 10팀 예선(랩 62건, 되돌리기, FA 달성 불가, 강등과 취소, 검사 순서 동률)을 Playwright로 8번 되풀이해 모두 통과. 공개 화면 반영 평균 0.05초. 저장 응답보다 공개 화면 갱신이 먼저 오면 운영진이 막 적은 다음 랩타임이 지워지던 것을 찾아 고쳤다(보낸 값과 같을 때만 비움).

### 테스트 사이트 (2026-10-26, 사용자 요청)
- 운영과 같은 프로그램을 데이터만 따로 두고 한 벌 더 띄워, 대회 전에 예선·본선을 연습한다.
- 데이터는 운영 DB 복사본(사용자 선택): 실제 팀·대진·일정·규칙·관리자 계정. 복사한 뒤 로그인 세션은 지우고, 모니터링 페이지는 열어 게시하고, 모니터링 관리 주소는 새로 만든다. 연습이 끝나면 같은 절차로 운영 DB 의 그때 상태를 다시 복사해 초기화한다(이 기계 전용 스크립트, 저장소 밖 설정).
- 화면(사용자 선택): `VITE_TEST_SITE=true` 로 빌드하면 모든 화면 맨 위에 주황 띠 '테스트 사이트 · 여기 기록은 실제 대회와 상관없습니다'가 나오고 탭 제목 앞에 [테스트]가 붙는다. `VITE_REAL_SITE_URL` 을 주면 띠에 실제 사이트 링크. 운영 빌드에는 나오지 않는다(Dockerfile 빌드 인자).
- 검색엔진에는 올리지 않는다(프록시에서 noindex 헤더). 로그인 쿠키 경로가 달라 운영과 테스트 로그인이 섞이지 않는다.

### 예선 랩타임은 0.01초 단위 (2026-10-28, 사용자 요청)
- 랩타임은 계시원 두 명의 기록을 평균해 소수 셋째 자리에서 반올림한다(규칙 4.1.2). 그래서 콘솔 입력은 소수 둘째 자리까지(`42.14`, `1:02.35`)만 받고, 소수 셋째 자리까지 적으면 형식 오류로 돌려보낸다.
- 서버도 10 ms 단위가 아닌 `lap_time_ms` 는 422로 거부한다. 저장 단위(정수 밀리초)와 DB 는 그대로라 마이그레이션은 없다.
- 표시도 `m:ss.SS`(예: `0:42.14`). 0.01초 단위가 아닌 예전 기록은 반올림해서 보인다.

### 대회 전 E2E·시뮬레이션에서 찾은 문제 (2026-11-01, 사용자 요청)
- 운영 DB 복사본으로 따로 띄운 서버에서 콘솔 화면 E2E(공개 페이지 → 비공개 → 예선 → 연결 끊김·재시작 → 랭킹·시드 → 본선 12경기 → 종료)와, 규칙 문서를 따로 옮긴 기준 모델과 서버를 비교하는 시뮬레이션(한 팀 랩 순서 2,047가지, 10팀 무작위 예선 400회, 본선 승패 4,096가지 전부, 무작위 진행 순서 300회, 기권 69가지)을 돌렸다.
- 고친 것:
  - 본선 경기가 하나라도 끝난 뒤 '랭킹으로 시드 채우기'를 막는다(409 BRACKET_STARTED). 경기 중 기권하면 랭킹이 당겨져, 다시 채우면 다른 팀이 8강 칸을 옮기거나 부전승으로 올라가야 할 상대 팀이 칸에서 빠졌다(규칙 5.1.3 과 다름). 경기 전에는 지금처럼 다시 채울 수 있다.
  - 한 매치의 두 팀이 모두 기권하면 그 결과를 기다리던 다음 매치를 끝낼 수 없었다(예: 플레이인 두 팀 기권 → 8강 Race 5 막힘). 앞 매치에 올 팀이 하나도 없으면 그 칸은 채워지지 않는 칸으로 보고 부전승으로 끝낸다.
  - 콘솔 '예선 자동 순위로 채우기'가 랩 기록이 없는 팀을 빠뜨려 그 팀의 시드 칸이 비었다(상대가 부전승). 규칙 4.7 로는 Q1 0랩이므로 맨 아래에 차량 검사 순서대로 넣고 알림을 보인다. 나오지 않은 팀이면 운영진이 뺀다.
  - 콘솔 최근 기록이 모든 팀의 최근 20건뿐이라, 팀당 6분에 20~36랩을 도는 실제 예선에서는 같은 팀의 앞쪽 랩도 금방 목록 밖으로 밀려 고칠 수 없었다. '볼 기록'에서 팀을 고르면 그 팀의 기록을 모두 보인다.
- 그대로 둔 것: 같은 팀 랩을 두 콘솔에서 같은 순간에 보내면 하나만 저장되고 나머지는 409(다시 누르면 됨). 여러 팀의 강등이 같은 자리로 겹칠 때는 아래 팀부터 옮긴다(규칙에 정해 있지 않음).

### 관리자 화면 본선 대진: 칸 끌어 놓기로 자리 바꾸기 (2026-11-01, 사용자 요청)
- 관리자 화면 > 본선 대진에서 칸을 끌어 다른 칸에 놓으면 확인 창(바뀌는 칸의 지금 팀 → 새로 올 팀)을 거쳐 두 칸의 자리를 바꾼다. 끌기 어려우면 칸 왼쪽 화살표 버튼으로 고른 뒤 '여기와 바꾸기'를 누른다(Esc 로 취소). 칸마다 폼으로 고치는 '수정'은 그대로 둔다.
- 사용자 결정: 바꾸는 것은 대진 칸(매치업)이고 결과 입력·되돌리기는 지금처럼 모니터링 관리에서만 한다. 칸 바꾸기는 로그인한 관리자만(모니터링 비밀 값으로는 안 됨, `POST /api/admin/bracket/slots/swap`).
- 팀만 옮기지 않고 칸을 채우는 방법(예선 순위·앞 매치 결과·자리표시)을 함께 바꾼다. 그래야 '예선 3위'·'Race 1 승' 표시가 팀을 따라가고, 경기 전 시드를 다시 채워도 옮긴 자리가 유지되며, 앞 매치 결과를 되돌리거나 다시 입력해도 옮긴 칸으로 전달된다. 두 칸의 정의를 맞바꾸므로 어떤 연결도 사라지지 않는다.
- 끝난 매치의 칸은 끌 수도 놓을 수도 없다(409 MATCH_FINISHED, 결과를 되돌린 뒤 옮긴다). 두 매치의 version 을 함께 보내 낡은 화면에서의 변경을 막고, 바꾼 뒤 같은 매치에 같은 팀·예선 순위·출처가 두 번 들어가거나 매치가 자기 결과를 기다리게 되는(순환) 경우는 422 로 거절한다. 변경 이력에는 'swap' 으로 남는다.
